# Prototype Instructions

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

After every user-directed code or visual iteration, always run the normal production build so `dist` and the desktop prototype reflect the latest source. Do not run smoke suites or other automated tests unless the user explicitly asks; confirm the requested result through implementation and the available preview instead.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

Build app UI in `src/`. Keep `.openai/hosting.json`, `worker/index.js`, `scripts/prepare-sites-build.mjs`, and `tests/sites-worker.test.mjs` intact so the same local prototype can be handed to Sites. Before a Sites handoff, run `npm run build` and `npm run test:sites`; the build must leave `dist/client/index.html`, `dist/server/index.js`, and `dist/.openai/hosting.json`.

## Desktop prototype testing

- Keep `Bean.command` as the directory-local, double-clickable macOS test launcher.
- Keep `Brizo.command` as the current branded, double-clickable macOS launcher; retain `Bean.command` only as a backwards-compatible launcher so existing user shortcuts do not break.
- The desktop test window must load `dist/client/index.html` directly through Electron and must not depend on Vite or another local web server.
- Preserve `npm run desktop:smoke` as the automated check for the local-file desktop runtime.
- External web pages in the desktop prototype must use an isolated Electron `WebContentsView`; keep Node integration disabled, context isolation and sandboxing enabled, and remote permission requests denied by default.
- Preserve `npm run desktop:browser-smoke` as the automated external-page runtime check.
- Use `npm run desktop:run` for normal local launches against an existing `dist`; `Brizo.command` and legacy `Bean.command` build only when `dist/client/index.html` is missing. Keep build-before-run behavior in smoke, distribution, and explicit `npm run desktop` workflows.
- Preserve `npm run perf:startup` as the repeatable local cold-process shell benchmark; treat its Chrome headless timing as directional rather than a like-for-like page-load score.
